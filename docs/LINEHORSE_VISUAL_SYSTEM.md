# LINEHORSE visual system

Primary reference: the user-supplied Sprint 6 LINEHORSE multi-screen mockup, `Photo 1.jpg`. It establishes dark blue-black framing, restrained copper accents, compact navigation, warm working panels and clear operational hierarchy. The exploratory horse mark is deliberately omitted. No mockup data, future modules, simulated permissions, search bar or notification controls are reproduced.

## Tokens and shared patterns

The single global stylesheet defines reusable tokens; Tailwind aliases preserve existing component contracts.

| Token | Value | Use |
| --- | --- | --- |
| shell | `#142330` | Navigation and selected calendar controls |
| shell-deep | `#101a23` | Brand/authentication surface |
| copper | `#a94f2b` | Primary actions, focus, section accents |
| brass (legacy alias) | `#d49660` | Restrained amber selection accents |
| background | `#f3f1ec` | Warm workspace |
| surface | `#fffefa` | Cards and fields |
| foreground | `#202b34` | Primary information |
| muted | `#59656b` | Supporting information |
| field-line | `#818b8e` | Visible form boundaries |

Use `PageHeader`, `Card`, `WorkspaceMetric`, existing labelled status components and the shared `button-primary`, `control`, `notice`, `record-stack`, `job-tabs` and calendar patterns. Decorative navigation glyphs come from `WorkspaceIcon`; text remains the accessible name. No new dependency or icon package is introduced. Existing Geist/Geist Mono are retained, with tabular numeric summaries and restrained type scales.

Trade colors remain generated by the established scheduling logic, independent of status. Status words and existing overdue indicators remain explicit. Do not substitute brand copper for trade identity or use color as the sole status signal. Summary values must come from authorized existing records; expected assignments are never labelled actual attendance.

## Responsive and accessible use

- Desktop: dark persistent navigation, company/user/role context bar, bounded workspace and compact record panels.
- Mobile: dark sticky header, Docs shortcut, native More disclosure for existing Resources/guide/logout, and labelled bottom navigation. The disclosure closes on navigation. It does not grant new access.
- Form controls have visible borders, 44px targets (48px mobile), native input semantics and 16px mobile input text. Labels, native validations, pending states, server errors and saved confirmation remain intact.
- Focus uses a visible copper outline; shell focus uses a light accent. Selected calendar controls retain aria-pressed and a separate amber underline. Reduced-motion preference is respected, and print styling removes navigation without hiding records.
- Keep loading/error/empty states truthful. Shared status/alert styling does not turn a pending or rejected write into success.

## Image provenance

`public/images/construction-framing.webp` is a generated decorative architectural photograph, created for Sprint 6 and lossily compressed using the existing Sharp dependency. It is not a customer/project photo or evidence. Used only on the desktop authentication surface, with empty alt text and local Next Image delivery. It is not repeated on operational screens, where actual project photos are currently absent from the test fixtures. No final logo is introduced. Future real project imagery must use existing authorized project sources; never invent record photos to resemble a reference mockup.

## Boundaries

The interface supports the existing multi-role company workspace. Displayed user and role come from the unchanged shell props and established identity architecture. No new roles, authorizations, APIs, database objects, RLS policies, attendance system or intelligence capability is introduced by styling.


## 2026-10-09 — Clarity at Every Level

They do not implement new role permissions or new screens.
