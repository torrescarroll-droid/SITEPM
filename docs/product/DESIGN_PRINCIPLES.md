# Clarity at Every Level

Preserve the [Sprint 6 visual system](../LINEHORSE_VISUAL_SYSTEM.md) and [actual before/after evidence](../SPRINT_6_VISUAL_TRANSFORMATION_2026-10-09.md#visual-evidence). This document extends design doctrine, not UI implementation or permissions.

**Power underneath. Clarity on the surface.** LINEHORSE should make sophisticated construction information understandable without making users learn the internal architecture. The superintendent's working desk is a valuable design lens, not the only role or the whole product.

## Shared language

Dark charcoal/midnight navigation, copper primary actions, restrained amber, warm neutral surfaces, sophisticated legible typography, clear hierarchy and useful density. Reuse tokens/components rather than one-off skins. Keep restrained industrial precision; avoid rustic/Western styling, excess gradients, repetitive hero photos, horse watermarks, animation or decorative dashboard filler.

Use genuine authorized project imagery where useful. Decorative generated authentication imagery is not project evidence. No horse asset is approved; the newer right-facing profile preference remains exploratory. Keep the current wordmark until explicit brand approval.

## One truth, purposeful views

| Responsibility | Design question / future presentation; not current permission capability |
| --- | --- |
| Field contributor | What do I need to do, capture, clarify or recover now? |
| Superintendent | Who is expected, what is ready, what changed and what needs coordination? |
| PM | Which evidence needs review, what is slipping and what decision is needed? |
| Executive/operations | Which projects/resources need intervention, using shared definitions and freshness? |
| Finance | Which approved progress/changes support the current application and reconciliation? |
| Client | What is approved to share, what is happening next and what decision is mine? |

Personalization changes presentation, never access. Use clear headlines, concise cards and progressive disclosure; “Show me the breakdown” opens permitted details and source evidence. One shared metric definition across views; no private cost leak in client aggregates. Preserve dense tables/calendars for users who need them, without forcing the same density on every role.

## Truthful interaction

- Trade identity stays stable; status uses words/icons as well as color. Expected presence, actual attendance, reported work and verified progress use distinct labels.
- Saved means server-confirmed persistence. Pending, failed, retryable, conflicted and locally saved states must be explicit. Avoid unconfirmed optimistic success.
- Current document means selected version, not approved instructions. Hash-verified source means intact bytes, not verified installation.
- Show as-of/freshness, scope, metric definition and preliminary/verified state. No invented percentages, weather, on-track labels or sample data presented as customer reality.
- Forms retain visible labels, usable touch targets, keyboard focus, accessible status/error feedback and safe confirmations. Responsive detail and drilldown must remain usable without horizontal page overflow.
- Photos/charts earn their space by explaining actual work or decisions. Simple charts need clear denominators/units; no visual polish disguising missing evidence.

## Validation doctrine

“Can the user understand the key state and next action in roughly three seconds?” is a research prompt, not a measured product guarantee. Test comprehension with actual contractors across roles and digital literacy. Track task completion, mistakes, recovery and support burden; preserve useful hierarchy as complexity grows. Check desktop and emulated mobile, then real phones, poor connection, keyboard and assistive technology where relevant. Emulation is not physical-device certification.

Keep a recoverable visual baseline. Refine through documented feedback; do not freeze the product or silently change established design direction. The supplied multi-screen mockup is inspiration, not a feature checklist, pixel-perfect mandate or approved logo sheet.
